# Phase 4 — Apple Watch Health Sync

> Status: ☐ Not started
> Gate: Phase 5 starts only after today's Watch steps appear on the Kindle dashboard.

## Goal

Apple Watch / iPhone Health data (steps, calories today) flows into `health_daily_summaries` and shows in the dashboard's STEPS/CALORIES gauges. Phase 4a is pure setup (the pipeline already exists in the repo); 4b is an optional exercise-minutes extension.

## 4a — Setup only (no code changes)

### Xcode build
1. Open `ios/HealthSyncCompanion/HealthSyncCompanion.xcodeproj` in Xcode (Mac).
2. Signing & Capabilities → select your **personal team** (free Apple ID works).
   - Free provisioning profiles expire after **7 days** → the app needs a weekly re-run from Xcode. A paid Apple Developer account ($99/yr) gives a 1-year profile. Start free; upgrade only if the friction annoys you.
   - HealthKit entitlement is already in `HealthSyncCompanion.entitlements`.
3. Configure the endpoint:
   ```sh
   cp ios/HealthSyncCompanion/Config/LocalConfig.example.xcconfig \
      ios/HealthSyncCompanion/Config/LocalConfig.xcconfig
   # then set:
   # INSFORGE_HEALTH_SYNC_URL = https://<project>.insforge.app/functions/health-sync
   # HEALTH_SYNC_TOKEN = <generated by kit:backend in Phase 0>
   ```
   Retrieve the token: `npx @insforge/cli secrets get HEALTH_SYNC_TOKEN` (see `--help` for exact verb).
4. Run on a **real iPhone** (HealthKit is useless in the simulator). Grant Health **read** permissions when prompted. Wear the Watch so steps/exercise populate.

### Pipeline already in place (verify, don't rewrite)
- `functions/health-sync.ts`: token-header auth, ≤45 days per batch, upsert by `(date, source)`
- `migrations/20260627000000_create-health-daily-summaries.sql` (applied in Phase 0)
- `kindle-dashboard-data.ts` `health` payload + C++ STEPS/CALORIES radials

## 4b — Optional: exercise minutes

Only if 4a is stable and you want the extra metric.

1. `migrations/20260712000000_add-exercise-minutes.sql`:
   ```sql
   ALTER TABLE health_daily_summaries
     ADD COLUMN IF NOT EXISTS exercise_minutes INTEGER NOT NULL DEFAULT 0 CHECK (exercise_minutes >= 0);
   ```
2. `functions/health-sync.ts`: accept `exercise_minutes` in `HealthDayInput`, clean/persist (respect the existing preserve-non-zero pattern).
3. `ios/HealthSyncCompanion/HealthKitSyncService.swift`: add `HKQuantityType` `appleExerciseTime` daily-sum query to the set; `HealthSyncModels.swift`: new field; client unchanged.
4. `functions/kindle-dashboard-data.ts`: include `exercise_minutes` (+ optional `exercise` target from `health_targets`) in the `health` payload.
5. `kindle_dashboard.cpp`: third small radial or text line `EXERCISE 30/30 MIN` under STEPS/CALORIES (reuse `drawRadialMetric`).
6. Update fixture JSON.

## Rollback / fallback

- Health rows are isolated by `source = 'apple_health_ios'` — zeros/staleness never affect lists or other panels.
- If the iOS build fails on signing: dashboard shows zeros; everything else unaffected; retry after fixing team/profile.
- 4b is purely additive — revert the migration + payload field + C++ line independently.

## Tests
